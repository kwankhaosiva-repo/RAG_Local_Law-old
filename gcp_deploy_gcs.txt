# LINE webhook หมายเหตุ:
# - webhook ประมวลผล LLM "ภายใน request" (await run_in_threadpool) แล้วจึงตอบ 200
#   (ห้ามย้ายไปทำหลัง response — ดูข้อ ⚠️ ด้านล่าง)
#   (LINE timeout สั้น)
# - ใช้ Reply API (ฟรี ไม่นับ quota) ถ้า token ใช้ไม่ได้ → fallback ไป Push API (นับ quota)
# - ใน LINE Developers Console: Webhook URL = https://<cloud-run-url>/line/webhook
#   ปิด auto-reply/greeting ของ Official Account และอย่าเปิด "Use grouped responses"
#
# ⚠️ ใช้ --cpu-throttling (default, ประหยัดสุด) ได้ — ห้ามย้ายงานตอบกลับไปทำ "หลัง" response
#   สาเหตุบั๊กเดิม: webhook ตอบ 200 แล้วใช้ BackgroundTasks/thread ทำงานต่อ → Cloud Run
#   โหมดประหยัดให้ CPU เฉพาะตอนมี request ค้าง → งานถูกอด CPU → บอทเงียบ
#   แก้แล้ว: src/line_bot.py ประมวลผล "ภายใน request" (await run_in_threadpool) →
#   webhook ตอบช้าลง (วินาที) แต่ CPU ยังอยู่ครบ → reply ออกเสมอ + ไม่มีค่าใช้จ่ายเพิ่ม
#
# - ไม่ต้องใช้ --no-cpu-throttling เลย (โหมดนั้นจะจ่าย CPU ตลอดเวลาแม้ idle)
#
# - --min-instances 0 (แนะนำ, ประหยัด): cold start เร็วขึ้นแล้วเพราะ embedding model
#   ถูกฝังใน image (Dockerfile pre-download) → ไม่ต้องโหลด ~470MB จาก Hugging Face
#   ครั้งแรกหลัง instance ถูกเก็บ จะช้า ~10-30 วิ (token อายุ ~1 นาที ยังทัน)
#   ถ้าต้องการเร็วทุกครั้งตลอดเวลา: --min-instances 1 (มีค่าใช้จ่าย idle rate แม้ CPU ถูก throttle)
